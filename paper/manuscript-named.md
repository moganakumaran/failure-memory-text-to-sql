# Failure Memory Does Not Help Text-to-SQL Agents: A Compute-Fair, Corrected-Label Evaluation

**Mogana Kumaran Sivaraman**
*Independent Researcher, San Francisco, CA, USA*

*This work was conducted independently by the author and does not reflect the views of any employer.*

**Keywords:** Text-to-SQL; LLM agents; episodic memory; agent evaluation; benchmark label quality; compute-fair comparison; schema drift

## Abstract

Episodic memory of past failures is widely assumed to help LLM agents, and memory mechanisms are a standard component of agent architectures. We test that assumption for Text-to-SQL agents over relational databases, under the evaluation conditions the claim actually requires: a pre-registered protocol, paired comparisons at matched token budgets, and scoring against both original benchmark labels and independently audited corrected labels. On a purpose-built split of 100 recurring-failure task pairs from BIRD, episodic memory does not improve pass@1 over a no-memory baseline in either of two implementations: failure-fingerprinted memory scores −1.8 points (95% CI −5.7…+2.1) and generic episodic memory −4.6 points (−9.5…0.0), at equal or greater token cost; the null replicates exactly (0.0 points, −4.6…+4.6) on an open-weight model, and holds at pass^k for k = 2 and 4. Under a purpose-built drift split (60 tasks, 55% silent semantic drift), memory frozen before the drift — the hypothesized stale-memory hazard — is exactly neutral on silent drift (0.0 points), and a paired control on identical tasks puts the drift effect itself at −8.3 points on original labels (−18.3…+1.7) and −15.4 on corrected labels (−27.1…−4.2). The study's one positive arm is diagnostic rather than decisive: generate-and-select beats no-memory by +9.8 points on original labels but by exactly 0.0 on corrected labels while running 17% over its nominal token budget — consistent with label noise and loose compute accounting jointly manufacturing an apparent win, though the corrected subset (49 tasks, ±8 points) cannot by itself exclude a real effect; under a strictly enforced cap in the replication, the same arm is null on original labels as well. A verifier ablation adds a further caution: the base agent's self-verifier is a net harm (−8.5 to −9.8 points), and the memory null persists without it. We release the evaluation design, the drift split construction, and a strict no-gold memory-acquisition methodology (56.5% acquisition rate) as reusable artifacts. Our conclusion is narrow and, we argue, useful: on this substrate, at matched compute, failure memory is not where the gains are — and evaluations that do not control labels and tokens cannot be trusted to say where they are.

## 1. Introduction

Agent memory is having its framework moment. Long-term episodic stores, reflection buffers, and failure libraries are built into most serious agent stacks, and the intuition behind them is appealing: an agent that has seen a failure before should not repeat it. For data agents — systems that answer questions by generating and executing SQL over enterprise schemas — the intuition seems especially strong, because failures recur: the same schema quirks, value formats, and join traps appear across questions on the same database.

Yet the evidence base for failure memory in data work is thin in a specific way. The strongest published multi-agent result on Text-to-SQL, CHASE-SQL, is a generate-and-select method whose gains come at explicitly higher test-time compute; it says nothing about memory. General-domain agent research offers a cautionary signal — consolidated LLM memory has been shown to degrade performance below a no-memory baseline in some settings, and recent work on stale retrieval and silent environment change shows memory hurting agents in ways retrieval metrics do not detect — but no published study, to our knowledge, tests failure memory for data agents at matched compute against audited labels. Meanwhile the labels themselves are suspect: a recent audit of BIRD and Spider 2.0 found annotation error rates above 50% on audited subsets, with leaderboard rank shifts of up to nine places after correction. An evaluation that ignores both problems — unmatched compute and noisy labels — can manufacture wins that do not exist.

This paper is the report of a pre-registered attempt to find out whether failure memory helps, designed so that a negative answer would be as informative as a positive one. Our protocol, hypotheses, exclusion rules, and go/no-go margins were frozen before any run and amended only through dated amendments. The answer, across two memory implementations, a drift condition, a verifier ablation, and an open-model replication, is no — and the study's one positive arm turns out to be an object lesson in why the controls mattered.

**Contributions.**

1. **A pre-registered, compute-fair test of failure memory for Text-to-SQL agents.** Two memory implementations (failure-fingerprinted and generic episodic), a no-memory baseline, and a generate-and-select arm, compared pairwise on identical task pairs with paired bootstrap intervals, at measured token budgets — plus a verifier ablation showing the base agent's self-verifier is a net harm and that the memory null is not a verifier artifact.
2. **Dual-label evaluation as a first-class control.** Every contrast is reported on original BIRD labels and on the corrected labels of Jin et al.'s audit (498 tasks). The study's headline methodological finding — a +9.8-point effect that is exactly 0.0 under corrected labels — is only visible because both views were pre-committed.
3. **A drift split for data agents, a paired drift measurement, and a stale-memory test.** Sixty execution-verified drifted database variants (55% silent semantic drift), a same-task undrifted control, and a frozen pre-drift memory arm let us measure both the drift effect and negative transfer directly: drift costs accuracy; stale memory is neutral.
4. **A strict memory-acquisition methodology.** Memory episodes are acquired only from agent-discovered, execution-verified remediations — gold SQL never touches the store — with the acquisition rate (56.5%) reported as a headline statistic, so a null result cannot be dismissed as an empty store.

## 2. Related work

**Benchmarks and the label problem.** BIRD (Li et al., NeurIPS 2023 Datasets & Benchmarks) is the standard large-scale Text-to-SQL benchmark: 12,751 question–SQL pairs over 95 databases, where GPT-4 reached 54.89% execution accuracy against 92.96% human performance. Spider 2.0 (Lei et al., ICLR 2025) moves to enterprise workflows, where a leading agent scored 17.0% (arXiv v1) to 21.3% (ICLR 2025 version) — a reminder that version matters when quoting results. Jin et al. audited both benchmarks and reported an annotation error rate of 52.8% on the BIRD Mini-Dev subset they audited, with corrected-label rank shifts of −9 to +9 places; their released corrections cover 498 BIRD Dev tasks, which is the set our corrected-label view uses (§3.1). Two recent audits reinforce the point from other angles: retrieval metrics can rank memory policies backwards when stored facts go stale (Murshed, 2026), and a task-level audit of eight frontier benchmarks found verified task validity of only 29.3% for multi-step suites against 92.5% for closed-form benchmarks (Zhu and Cat, 2026). Label and metric validity is a live methodological problem, not a niche concern of this study.

**Data agents.** Multi-agent Text-to-SQL is an active design space. CHASE-SQL (Pourreza et al., ICLR 2025) reported the highest BIRD execution accuracy among multi-agent systems at its time (73.01% dev, 73.0% test), achieved by generating diverse candidates and selecting among them at additional test-time compute — the design our A3 arm mirrors under a budget cap. Earlier multi-agent systems include MAC-SQL (COLING 2025; Selector/Decomposer/Refiner; 59.39% dev in the paper, 57.56% on the official leaderboard — we note the discrepancy), MAG-SQL (61.08% on BIRD with GPT-4), and CHESS (dev ≈65–68%, test ≈67–71% depending on configuration). DIN-SQL (NeurIPS 2023) reaches 50.72% dev with a single model under decomposed prompting — a reminder that decomposition gains are not inherently multi-agent. None of these systems uses cross-session failure memory; their gains, where real, come from within-task compute. SQLAgent (Jiang et al., Findings of ACL 2026) takes a different route, learning to explore the database before generating SQL; exploration targets exactly the schema-grounding failures that dominate our error taxonomy (§3.5). Broader data-analysis benchmarks (DSBench; DABstep; DataAgentBench) report best-agent accuracies in the 14–57% range depending on version and subset, underscoring how unsettled data-agent evaluation remains.

**Agent memory.** The canonical memory mechanisms are general-domain. Reflexion stores verbal self-reflections in an episodic buffer and reuses them across trials; ExpeL pools raw trajectories and distils cross-task insights for recall at inference; Generative Agents maintain a memory stream with reflection synthesis; MemGPT (Packer et al., 2023) popularized tiered, OS-style memory. None of these was evaluated on Text-to-SQL or any data-agent task. Evidence that memory helps is mixed even in general domains: Zhang et al. show that *consolidated* LLM memory degrades with repeated updating and can fall below a no-memory baseline, while an episodic-only control retaining raw trajectories remains competitive. A newer line of work treats memory as a liability surface: stale retrieval that standard metrics score as correct (Murshed, 2026), silent environment change under which experienced agents fail where novices succeed (Xu et al., 2026), and "memory-induced degradation" from following wrong stored lessons (Lee et al., 2026). Our A1/A2 arms implement the episodic family directly — raw traces, no LLM consolidation — so the null we report is a statement about the strongest form of the memory hypothesis in this literature, not about a strawman. Whether raw episodic memory helps *data* agents was, to our knowledge, untested before this study; the gap analysis underlying it (two scoped passes over arXiv and major venues, November 2026) found the cell empty.

**Reliability measurement.** τ-bench (Yao et al., 2024) introduced pass^k — the probability that all k independent runs succeed — as a reliability metric for agents, showing steep degradation (GPT-4o below 25% at pass^8 in retail). Our frozen claim was stated in pass^k terms; the study's pre-committed gate used run-mean pass@1, and §5.7 reports pass^k for the primary contrasts. Failure taxonomies for multi-agent systems (e.g., MAST, Cemri et al., NeurIPS 2025 Datasets & Benchmarks) are general-domain; our taxonomy (§3.5) is derived blind from data-agent traces.

## 3. Method

### 3.1 Substrate and label policy

The substrate is classic BIRD Dev (dev_20240627, pinned): 1,534 tasks over 11 databases. Because label quality is a variable in this study, every task carries a label status: **L1** corrected label available from Jin et al.'s audit (498 tasks; 220 with SQL differing from the original gold); **L2** original label only (1,035 tasks); **L3** disputed, no correction — excluded from all primary metrics and logged (1 task: question 1006, a gold error discovered by this study's dry runs, in which the gold's string-parsing ordering returns a 2:00.000 lap as "fastest" while the milliseconds column's minimum is 1:07.411; verified by direct execution and corroborated by two independent models); **L4** ambiguous (0 tasks). All results are reported dually, on original labels for the full primary set and on corrected labels for the L1 subset. The manifest, splits, and all file hashes were frozen before the study; the single post-freeze change (the L3 relabelling of q1006) was made by dated amendment with the original hash preserved.

### 3.2 Splits

**Repeated-failure split.** One hundred Session-1/Session-2 task pairs, clustered by database and identical table-set signature, balanced 9–10 pairs per database. Pair similarity is a structural distance, 1 − [0.5·Jaccard(table sets) + 0.3·Jaccard(SQL skeleton tokens) + 0.2·Jaccard(question tokens)]; observed distances run 0.086–0.307 (median 0.209) — all pairs are structurally similar recurrences, spanning a band from near to moderate similarity rather than a similar/dissimilar contrast. Pairs below distance 0.10 (3 pairs) are flagged recall-control and excluded from the primary metric, leaving 97 primary Session-2 tasks; results are also stratified by distance tertile. Session 1 is where memory is acquired; Session 2 is where it is tested. Memory for a task comes only from strictly earlier sessions; Session-2 acquisitions are written to a shadow store that is counted but never retrieved within the study. A violation invalidates the run (none occurred).

**Drift split.** Sixty tasks, all L1, each with a drifted copy of its database built by one of seven operators (column rename 23, value recode 10, category merge 9, unit change 9, type change 4, temporal grain 4, null semantics 1). Thirty-three variants (55%) are *silent* — the meaning changes under unchanged column names — and 27 are overt renames, which serve as the control condition. Every variant was verified by execution before freezing. Figure 1 shows the composition by operator. Scoring on the original-label view uses the drift-adjusted original gold executed on the drifted database. Scoring on the corrected-label view executes Jin et al.'s corrected SQL — written for the original database and not itself drift-adjusted by hand — against the drifted database; §7 records what this does and does not limit.

**Figure 1.** Drift-split composition: 60 execution-verified variants by operator, split into silent (33) and overt (27).

### 3.3 Arms

All arms share one base agent: schema + evidence + question → SQL generation, read-only execution with a 10-second limit, retry on execution error with the error fed back (maximum 3 attempts), and a self-verification step in which the agent's own verifier accepts or revises the result. Prompts, tools, sandbox, and step limits are identical across arms; only the memory/selection mechanism varies. (The verifier itself is ablated in §5.6.)

- **A0 — no memory.** The base agent, stateless across sessions.
- **A1 — failure-fingerprinted episodic memory.** Episodes are raw traces keyed by a deterministic fingerprint over (failure class, error signature, schema elements, schema version). Retrieval is exact fingerprint match, else top-k (k ≤ 3) embedding retrieval over raw traces. No LLM consolidation is applied to stored episodes. Retrieval embeddings are produced locally (a Qwen2.5-Coder-3B model served via Ollama, with a hashed term-frequency fallback in the harness); §7 discloses a logging gap in which backend served the study runs.
- **A2 — generic episodic memory.** The same store and retrieval budget without fingerprint keying (embedding similarity retrieval only). §5.3 reports how the two implementations actually differed in behavior.
- **A3 — generate-and-select.** Three candidates are generated and executed; a selector call picks among those that executed, in the style of CHASE-SQL. Its token budget is capped at A1's measured average tokens per task (3,506) — see §5.2 for how that cap behaved as implemented, and §5.5 for the fix applied in the replication.
- **A4 — stale memory (drift split only).** A1's mechanism with the store built on the original databases before drift (16–22 episodes per run), frozen at the drift boundary, and never updated during the drift phase. A1's drift-phase store, by contrast, starts empty and grows during the phase (72 episodes acquired).

### 3.4 Memory acquisition policy

The acquisition rule is the methodological core of the study, because a memory evaluation is only meaningful if the memory could plausibly have been built in deployment. An episode enters the store **only** when the agent itself recovers from a failure during a task — an execution error or a verifier rejection — and the remediation is verified by execution and accepted by the agent's own verifier. Gold SQL, gold labels, and human fixes never create, complete, or repair an episode. Failures the agent cannot resolve go to a separate unresolved log. The **acquisition rate** — episodes acquired divided by failures the agent observed — is reported as a headline statistic alongside accuracy, so that a null accuracy result can be checked against the possibility that the store was simply empty. The rule is enforced in harness code, not by convention.

### 3.5 Failure taxonomy

Failure classes were derived by blind open coding of dry-run traces (two annotators, 100% per-task primary-defect agreement on the local-model run; seed classes admitted only at reconciliation), then frozen before the study: F1 wrong schema link, F2 stale schema assumption, F3 wrong join/fan-out, F4 aggregation/grouping incl. temporal-snapshot semantics, F5 value-format mishandling, F6 unrecovered execution error, F7 correct content in the wrong answer shape, F8 unsafe/destructive (log-only), F9 no-change repair loop (a new class from open coding: the agent resubmits byte-identical SQL after error feedback — observed in 8 of 8 retries of a 3B local model, absent at frontier scale). Gold-label errors are not failure classes; they are handled by the label policy in §3.1.

## 4. Experimental setup

**Pre-registration and power.** The protocol — claim, arms, splits, exclusion rules, analysis plan — was frozen before any run, and changed afterwards only through dated amendments (A1–A14), which are released with the study artifacts. A simulation-based power analysis from dry-run base rates (per-task latent success probabilities, 4 runs per task per arm, paired test on run-mean pass@1) found power nearly invariant to base rate in [0.30, 0.55], with a minimum detectable effect at 80% power of 10–12 points at n = 100. The pre-committed GO margin for the memory hypothesis was therefore +12 points of paired pass@1 (A1 − A0) with the 95% CI excluding zero; the protocol pre-committed that a null would pivot this paper to the compute-fair negative-result framing rather than quietly change the claim.

**Model and harness.** The main study uses a single pinned snapshot, gpt-5-mini-2025-08-07, via API, at the provider's default sampling settings for this model family; §5.5 replicates the primary contrasts on Qwen2.5-Coder-32B-Instruct. Four runs per task per arm throughout. Scoring is execution accuracy: the predicted result set is compared with the gold result set as a multiset, order-sensitive when the gold query has ORDER BY. The full prompt set, including the verifier prompt, is released with the artifacts. Total cost of the main study was $14.91 across 3,760 trajectories (2,800 repeated-split, 960 drift); the replication cost $2.37 and the post-critique control and ablation runs (Amendment A14) $2.81, all inside pre-set budget caps recorded in the amendments.

**Analysis.** The pre-registered primary contrast is A1 − A0 on the repeated-failure split; all other contrasts are secondary and reported with the same paired machinery so the reader can judge multiplicity directly. Primary contrasts are paired per-task differences in run-mean pass@1 with task-level bootstrap 95% CIs (10,000 resamples, fixed seed). Token fairness is reported dually: attempt-matched (same step limits) and token-measured (actual mean tokens per trajectory per arm), with token-matching treated openly as an approximation.

## 5. Results

Figure 2 summarizes the main study's and replication's primary contrasts by split and label view; the subsections below give all numbers in full, including the Amendment A14 control and ablation runs.

**Figure 2.** Paired pass@1 differences (percentage points) with bootstrap 95% CIs, for the arm contrasts on the repeated-failure split (original and corrected labels), the drift split, and the Qwen2.5-Coder-32B replication (original and corrected labels). The dashed line marks the pre-committed +12-point GO margin.

### 5.1 Failure memory does not help (primary contrast)

On the 97 primary Session-2 tasks, the no-memory baseline A0 scores 0.539 pass@1. Failure-fingerprinted memory (A1) scores 0.521: a paired difference of **−1.8 points (95% CI −5.7…+2.1)**. The pre-committed GO criterion (+12 points, CI excluding zero) fails by a wide margin, and the interval rules out any true gain larger than ≈2 points in this regime — an informative null, not merely an underpowered one. On the 49 primary tasks with corrected labels the difference is −1.0 points (−6.1…+4.1). Stratified by pair-distance tertile, no stratum is significantly positive (near −3.8, mid +0.8, far −2.3 points, all intervals spanning zero): the null is not hiding among the most similar task pairs.

The store was not empty. In Session 1, A1 observed 177 failures and acquired **100 verified episodes (acquisition rate 0.565)** under the no-gold policy of §3.4; 77 failures were unresolved and logged. A1's Session-2 trajectories used a mean of 3,506 tokens against A0's 2,862 (+22%, the injected memory context) at essentially identical attempt counts (1.69 vs 1.68). Memory cost more compute and returned nothing.

### 5.2 Generate-and-select: a label-dependent win, over budget

A3 is the study's only positive arm on original labels: 0.637 pass@1, beating A0 by **+9.8 points (+4.1…+16.0)** and A1 by **+11.6 (+5.7…+18.0)**. On the 49 corrected-label tasks, however, both differences collapse — **0.0 points vs A0 (−8.2…+8.2)** and +1.0 vs A1 (−7.7…+10.2). Two readings remain live: the original-label win is a label-noise artifact (generate-and-select is better at matching buggy golds), or the 49-task subset is underpowered (±8 points) and cannot exclude a real effect. The data as they stand cannot distinguish these, and we report both views rather than claim the win. The replication (§5.5) adds one supporting leg for the artifact reading: under a strictly enforced token cap, A3 is null on original labels too.

A3 also exposes a fairness failure in our own harness: its mean cost was **4,102 tokens per trajectory, 17% over the 3,506 cap**, because the cap check ran before each candidate-generation call while the selector call sat outside it. A nominally token-matched arm was therefore not token-matched. We report A3 as-run with this caveat; the replication (§5.5) enforces the cap over the whole trajectory, selector included.

### 5.3 Generic memory is also null — and the fingerprint rarely fired

A2 scores 0.492 pass@1: **−4.6 points vs A0 (−9.5…0.0)** and −2.8 vs A1 (−7.7…+1.6) on original labels; on corrected labels, −4.6 (−10.7…+1.0) and −3.6 (−7.7…+0.5) respectively. Unlike A3, A2 was genuinely token-matched (3,463 mean tokens vs A1's 3,506; 1.70 attempts). The memory null therefore holds for generic episodic retrieval at equal compute.

One qualification matters for interpreting the A1–A2 comparison. A2 was designed to isolate the fingerprint mechanism, but the traces show the fingerprint path barely fired: of A1's 400 Session-2 trajectories, 364 retrieved at least one episode, yet only **9 trajectories (35 of 808 retrieved episodes, 4.3%)** involved a fingerprint-path hit; the remaining 355 retrieved through the same embedding path A2 uses (A2: 373/400 trajectories retrieved, all by embedding). The exact fingerprint key — failure class, error signature, and schema overlap jointly — is too strict to fire at this store size. What the study therefore tests is best described as embedding-retrieved episodic memory with and without a rarely-active fingerprint fast-path, and the fingerprint mechanism itself, at this strictness, is nearly inert — a mechanism finding we report as such, and a bound on what our null says about fingerprint designs in general.

### 5.4 Drift: a paired effect, neutral stale memory

An undrifted control run (Amendment A14) — A0 on the original databases for exactly the 60 drift tasks — separates the drift effect from task difficulty. The drift tasks are intrinsically harder than the repeated split (undrifted A0: 0.392 original labels, 0.446 corrected). The **paired drift effect** on identical tasks is **−8.3 points on original labels (−18.3…+1.7, not significant)** and **−15.4 points on corrected labels (−27.1…−4.2, significant)**. Drift is a real but moderate accuracy cost — not the halving that a naive cross-split comparison would suggest.

Against the drifted baseline (A0 0.308 original, 0.292 corrected):

| Contrast | Original labels | Corrected labels |
|---|---|---|
| A1 − A0 (live memory) | −4.6 (−9.6…+0.4) | −0.8 (−5.0…+3.3) |
| A4 − A0 (stale memory) | −1.7 (−6.3…+2.9) | +1.3 (−2.9…+5.4) |
| A4 − A1 (stale vs live) | +2.9 (−2.1…+7.9) | +2.1 (−1.7…+6.7) |

Stale memory (A4) is within ±2 points of no-memory overall and **exactly 0.0 on the 33 silent-drift tasks** (−5.3…+4.6) — the condition where pre-drift episodes were hypothesized to mislead most. A4's frozen stores were not empty (16–22 episodes per run, §3.3), so the neutrality is not an empty-store artifact. Live memory (A1) is likewise null under drift on corrected labels. With 60 tasks the intervals are ±5–12 points, so a small stale-memory harm cannot be excluded; the hypothesized *direction* of harm, however, is not observed anywhere in the split.

### 5.5 Replication on an open-weight model: the memory null is not a single-model artifact

We replicated the repeated-failure split (arms A0/A1/A3; A2 and drift not replicated) on **Qwen2.5-Coder-32B-Instruct via OpenRouter** — same substrate, splits, prompts, harness, scoring, and analysis, at a total cost of $2.37. The replication's A3 cap was A1's measured mean in the replication itself (1,614 tokens) and, unlike the main study, was enforced over the whole trajectory including the selector call. One process disclosure, in the spirit of this paper: the replication's first A3 run was discarded before analysis after we found a flaw in the cap estimator (it systematically under-budgeted the first candidate call; 36% of trajectories had made zero attempts), the estimator was fixed under a dated protocol amendment (A13), and A3 was re-run in full. The discarded run is preserved in the artifacts.

The headline result is a second, independent null for failure memory: A0 and A1 both score **0.583 pass@1**, a paired difference of **exactly 0.0 points (95% CI −4.6…+4.6)** on the 97 primary tasks. A3 is also null in the replication (+0.8 vs A0, −6.4…+8.3). On corrected labels (49 tasks), A1−A0 is +3.1 points (0.0…+8.2) — the interval touches zero and is not a significant effect — and A3−A0 is +4.1 (−4.1…+12.2).

Two caveats qualify the replication, and we report both. First, Qwen's memory store was thin: its Session-1 acquisition rate was **0.132 — 27 verified episodes from 205 agent-observed failures** (execution errors or verifier rejections); a further 32 Session-1 failures were silent — wrong results the agent never detected — and never entered acquisition. Mini's 0.565 rate against Qwen's 0.132 is itself a finding: acquisition depends on the agent noticing its failures, and models differ sharply in how often they do. (In 22% of Qwen's multi-attempt Session-1 trajectories it resubmitted byte-identical SQL after error feedback — the F9 no-change repair loop.) Mini's null is "memory, well stocked, did not help"; Qwen's is partly "memory, thinly stocked, did not help" — though retrieval still occurred in 184 of 400 Session-2 trajectories. Second, the enforced whole-trajectory cap *truncated* A3 rather than matching it: 89% of A3 trajectories hit the cap fallback, only 72/400 ran the full 3-candidate procedure, and 22% relied on a single capped "mercy" call. Mini's A3 ran the full procedure 17% over budget; the replication's ran a truncated procedure within budget. The replication's A3 null therefore cannot be read as a clean refutation of mini's original-label A3 win — but the corrected-label A3 contrast is null in both models (0.0 mini, +4.1 replication), so the label-sensitivity finding is consistent across models.

Taken together: the failure-memory null now spans two models, two token regimes (A1 at 3,506 vs 1,614 mean tokens), and two very different acquisition rates. Model identity moves the baseline level (Qwen's no-memory 0.583 vs mini's 0.539) but does not move the memory contrast.

### 5.6 Verifier ablation: the self-verifier is a net harm, and the null is not its artifact

The base agent's self-verifier could in principle absorb exactly the corrections memory would supply, making the memory null an artifact of agent design. An ablation under Amendment A14 — arms A0/A1 on the repeated split with the verifier disabled (executed SQL accepted immediately), 4 runs, 1,600 trajectories — answers this directly, and the answer has two parts.

First, the verifier is not a hidden helper; it is a **net harm**. Removing it *raises* A0 from 0.539 to **0.624** and A1 from 0.521 to **0.619**: the paired verifier effect (on − off) is **−8.5 points for A0 (−14.2…−3.4)** and **−9.8 for A1 (−15.7…−4.1)**. In this regime the verifier's REVISE step damages more correct answers than its rejections rescue.

Second, the memory null persists without the verifier: A1−A0 = **−0.5 points (−3.9…+2.6)** on original labels and +2.0 (−4.1…+8.2) on corrected labels. One caveat is structural and we state it plainly: the ablation's A1 store was thin — 2–3 episodes per run, with retrieval in only 18 of 100 Session-2 trajectories per run — because in this architecture acquisition is verifier-coupled. Without verifier rejections, the only acquisition events are execution-error recoveries (11 in 400 Session-1 trajectories; this model's failures are mostly silent). The ablation therefore answers the verifier question decisively but is a weak memory test by construction. That coupling is itself a design finding: memory acquisition that depends on verifier signals inherits the verifier's failure modes — here, a stock of episodes selected by a component that is itself net-harmful.

### 5.7 Reliability: pass^k

The frozen claim was stated in terms of pass^k, so we report it for the primary contrasts (τ-bench estimator C(c,k)/C(4,k) over the 4 runs per task; paired differences, original labels, 97 primary tasks):

| Contrast | pass@1 (pass^1) | pass^2 | pass^4 |
|---|---|---|---|
| Mini A1 − A0 | −1.8 | −2.2 (−7.6…+3.1) | −3.1 (−10.3…+4.1) |
| Replication A1 − A0 | 0.0 | +0.3 (−4.6…+5.0) | **0.0 (−5.2…+5.2)** |
| Drift A4 − A0 | −1.7 | −0.6 (−6.4…+5.0) | −1.7 (−8.3…+5.0) |

The null holds at every k, in both models — in the replication it is exact at pass^4 as well as pass@1. Absolute levels: mini A0 degrades from pass^1 0.539 to pass^4 0.443, while Qwen's pass^4 (0.567) barely drops from its pass^1 (0.583) — the open model is far more run-consistent at temperature 0, a reminder that pass^k measures a model property as much as a method property. On corrected labels, mini's A1−A0 is −3.7 at pass^2 and −6.1 at pass^4 (−18.4…+6.1), again null.

## 6. Discussion

Three conclusions survive both label views. First, **episodic failure memory does not improve Text-to-SQL accuracy at matched compute on recurring failures** — in two implementations, two models, and at every k — despite a healthy acquisition rate and a store built under deployment-realistic rules. Whatever limits this agent on Session-2 tasks, it is not a lack of remembered failures. Within the similarity band studied (all pairs structurally similar, distances 0.086–0.307), the null does not vary with pair distance, so "the pairs were not similar enough" is not supported as an explanation inside this band; the near-duplicate regime below distance 0.10 was excluded by design and remains untested (§7). Candidate mechanisms our data suggests but does not adjudicate — retrieved episodes acting as distractors (+22% tokens for no gain), Session-2 failures dominated by classes memory cannot fix (e.g., F7 answer-shape errors) — are listed as hypotheses.

Second, **evaluation hygiene is not a formality; it changes the answer.** The same study, scored two ways, produces a +9.8-point method win and a 0.0 null. Combined with a 17% budget overshoot inside a nominally capped arm, the A3 result is a concrete demonstration that label audits and whole-trajectory token accounting are load-bearing for agent evaluation claims — including, we note, claims made for memory systems evaluated without them. The verifier ablation adds a third hygiene item: a standard agent component, assumed beneficial, was worth −9 points until someone ablated it.

Third, **drift is an agent-robustness problem, not a memory-poisoning problem.** Measured properly — paired, on identical tasks — drift costs 8 points on original labels and 15 on corrected labels, while stale memory is neutral even under silent semantic change. Effort spent on stale-memory invalidation for this class of agent may be misallocated relative to effort spent on drift detection and re-exploration — a prioritization claim our data supports directionally, at this scale.

## 7. Limitations and threats to validity

- **Scope.** All results use one benchmark (BIRD Dev), one task family (Text-to-SQL), and two non-frontier models (gpt-5-mini-2025-08-07; Qwen2.5-Coder-32B-Instruct). The title's claim is scoped accordingly. Whether failure memory helps frontier-scale models, other data tasks (analytics, data engineering), or other benchmarks is untested; the capability-dependence reported for guideline memory in general domains (Jayaram et al., 2026) makes the frontier case a genuinely open question, and we flag it as the first follow-up.
- **Corrected-label coverage.** Corrected labels exist for 498 of 1,534 tasks (about one-third audited); corrected-label contrasts run on 49 primary tasks with ±8-point intervals. The A3 label-flip is therefore reported as "does not survive corrected labels," not as proof the original-label effect is spurious.
- **Drift power and scoring.** Sixty drift tasks yield ±5–12-point intervals; small stale-memory effects in either direction are not excluded. The corrected-label drift view executes Jin et al.'s corrected SQL — written against the original database — on the drifted databases; it was not drift-adjusted by hand, so that view measures the agent against the corrected *intent* under drift rather than against a hand-adapted corrected gold.
- **Token-matching is approximate.** Even with per-call caps, input-token growth from injected context makes exact equality across arms impossible; we report measured tokens for every arm so readers can re-normalize.
- **Embedding logging gap.** Retrieval embeddings were produced by a local model (Qwen2.5-Coder-3B via Ollama) when it was available, with a hashed term-frequency fallback in the harness; the study traces did not record which backend served each retrieval, so we cannot establish the serving mode per run from the artifacts. The released harness records it. We judge the risk to the conclusions low — the fingerprint analysis (§5.3) shows retrieval was dominated by whichever embedding path served both A1 and A2 — but we disclose it rather than guess.
- **Ablation store thinness.** The verifier ablation's memory store was thin by construction (§5.6); it answers the verifier question, and only weakly re-tests memory.
- **Regime.** Pair distances (0.086–0.307, median 0.209) represent moderate recurrence; the near-duplicate regime (distance < 0.10) is represented only by 3 recall-control pairs excluded from the primary metric. Memory might also behave differently in deployments longer than two sessions.

## 8. Conclusion

Under a frozen protocol, at matched compute, against both original and audited labels, failure memory did not help a Text-to-SQL agent — in two implementations, on two models, on recurring failures, and under drift, where stale memory also did not hurt. The study's one apparent win did not survive corrected labels, and its replication under an enforced token cap was null on both label views. We read this less as a verdict on memory in principle than as a measurement of where the burden of proof now sits: claims that agent memory helps — and agent evaluation results generally — should be required to survive corrected labels and whole-trajectory compute accounting before they are believed. The splits, acquisition methodology, and protocol record released with this paper are intended to make that standard cheap to meet.
