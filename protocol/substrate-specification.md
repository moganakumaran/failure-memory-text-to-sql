## 2. Target composition (from Frozen Protocol v2)
- Repeated-failure split: ~60 tasks, organised in failure-class clusters across sessions.
- Drift split: ~40 tasks derived from the repeated-failure tasks (same base tasks, drifted databases), at least half silent drift.
- Dry run: ~10 tasks, drawn first, used for taxonomy blind labelling and the power analysis. Dry-run tasks are NOT reused in the pilot splits.

## 3. Label policy (pre-committed)
For every candidate task, assign exactly one label status:
- L1 Corrected available: Jin et al. corrected gold exists → use corrected gold as primary; retain original gold for dual reporting.
- L2 Original only, not audited: no corrected label exists and the task was not flagged in the audit → usable; primary metric uses original gold, flagged L2 in the manifest.
- L3 Disputed, no correction: audit flags an annotation error but no corrected gold is released → EXCLUDE from all primary metrics; may be listed in an appendix set, never silently dropped (log in Section 6).
- L4 Ambiguous / multiple defensible answers: if, during inventory, a task is judged to have more than one defensible correct answer and no corrected gold resolves it → EXCLUDE from primary metrics, log with reason.
Dual reporting (Frozen Protocol §2): every headline result is reported on corrected labels (L1) and on original labels, separately.

## 4. Selection rules (in order; no discretion beyond these rules)
1. Start from the full BIRD Dev candidate pool only (amended, 2026-11-22). Record pool size at inventory.
2. Remove L3/L4 tasks. Log every removal.
3. Stratify the remaining pool by: database, and difficulty proxy (gold SQL length / number of joins / number of tables touched — computed mechanically from gold SQL, recorded per task).
4. Dry run first: randomly sample ~10 tasks across strata (seed recorded below once drawn).
5. For the repeated-failure split, cluster candidate tasks by the failure opportunity they present (shared schema elements, shared join patterns, shared aggregation/metric patterns) — clustering is by task/database structure only, NOT by any agent run, so selection cannot favour the method. Within each cluster, order tasks into Session 1 / Session 2+ by the similarity-distance rule in Frozen Protocol §3a; compute and store all three distance measures per pair.
6. Near-duplicate rule: pairs above the near-duplicate threshold (to be set from the distance distribution at inventory, and recorded here before any runs) go to the recall-control set, not the primary split.
7. Drift derivation: for each selected repeated-failure base task chosen for the drift split, apply exactly one drift operator from Frozen Protocol §3b, chosen by rotation across operator types so silent operators make up at least half. Record operator, target column/table, and pre/post schema version per task.
8. Balance check: before freezing the manifest, report counts by source, database, label status, cluster, session, and drift type. If any stratum is empty or dominates (>50% of a split), document why or re-sample under the same rules — and log the change.

## 5. Task manifest (one row per task; this is the pilot's ground truth file)
Columns: task_id | source (BIRD Dev, pinned version) | source_task_id | database | question | gold_sql_original | gold_sql_corrected (nullable) | label_status (L1–L4) | split (dry-run / repeated / drift / recall-control / excluded) | cluster_id | session (1 / 2+) | similarity distances to session-1 partner(s) | drift_operator (nullable) | drift_type (silent / overt / none) | schema_version_pre | schema_version_post | difficulty proxies | exclusion_reason (nullable)
The manifest is frozen (hash + date recorded in Section 7) before the first pilot run. Post-freeze changes require a dated amendment here and in the protocol.

## 8. What this specification does NOT do
- It does not select tasks by expected agent failure — failure classes come from the dry run's blind labelling, after selection.
- It does not import anything from the author's previous papers (author instruction, 2026-11-22: reference only).
- It does not claim the datasets or corrected labels have been inspected yet — see the honesty note in Section 1.
